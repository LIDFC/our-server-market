# OurServerMarket

Рынок предметов для Paper-сервера `mc.vin-off.site`. Без внутриигровой валюты: игроки меняются настоящими предметами,
а плагин держит их в эскроу, пока сделка не завершится.

Главное свойство — **предмет существует ровно в одном месте**: в инвентаре игрока, в эскроу рынка или в очереди выдачи.
Всё остальное подчинено этому.

## Что умеет

- **Раздача** — отдать вещь даром, забирает первый желающий.
- **Обмен** — «отдаю 16 алмазов, хочу 32 золота», с подтверждением обеих сторон.
- **Заявка** — «ищу элитры, отдам 20 алмазов и 2 незеритовых слитка».
- **Подарок** — конкретному игроку, забрать может только он.
- **Очередь выдачи** — если инвентарь полон или игрок не в сети, предметы ждут в базе, а не падают на землю.
- **Локальный API** для будущего раздела на сайте: список лотов, сделки, посылки, лента событий и несколько действий.

## Требования

- Paper 1.21.11, Java 21;
- Ubuntu (сервер запускается через `screen`);
- SQLite-драйвер **ставить не нужно**: Paper скачивает его сам по записи `libraries` в `plugin.yml`;
- AuthMe не обязателен, но если он стоит (у нас стоит), плагин дожидается входа игрока, прежде чем что-то выдавать.

## Установка

1. Соберите jar (или возьмите из GitHub Actions → Artifacts → `OurServerMarket`).
2. Положите в `/home/ubuntu/minecraft/plugins/`.
3. Перезапустите сервер — появится `plugins/OurServerMarket/config.yml` и `market.db`.
4. Задайте токен API (лучше переменной окружения `OUR_SERVER_MARKET_TOKEN`) и перезапустите ещё раз.

Пошагово, с командами для `screen`, — [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).

## Настройка

```yaml
database:
  file: market.db          # внутри plugins/OurServerMarket/

api:
  enabled: true
  bind: "127.0.0.1"        # наружу API выставлять нельзя
  port: 8788
  token: ""                # лучше пусто, а секрет в OUR_SERVER_MARKET_TOKEN
  rate-limit-per-minute: 120

listings:
  max-items: 27
  expire-after-days: 0     # 0 — лоты не истекают; иначе вещи вернутся владельцу
```

Без токена (или если он короче 24 символов) API просто не поднимается — плагин в игре работает как обычно.

## Окна

`/market` открывает обычное сундучное меню: смотреть рынок, отдать даром, предложить обмен, мои лоты, мои сделки,
посылки. Лот собирается галочками по собственному инвентарю — **предметы никогда не лежат в окне рынка**, они уходят
одной транзакцией в момент подтверждения. Поэтому окно нельзя использовать для дюпа: в нём нечего дублировать.

В окне сборки обмена или заявки у мыши две роли: **ЛКМ по вещи — «я это отдаю»**, **ПКМ — «я такое хочу взамен»**
(вещь, отмеченная как желаемая, остаётся у игрока, это просто пожелание). На каждой отмеченной вещи написано, в какую
половину она попала, а изумруд «подтвердить» перечисляет обе половины по пунктам — нажимать вслепую не приходится.
Когда игрок отвечает на чужой лот, рядом показан сам лот: что он получит и что за это просили. В «Моих сделках»
каждая сделка расписана так же — что вы отдаёте и что получаете.

Все команды ниже продолжают работать: окно — это удобство, а не единственный путь.

## Команды

| Команда | Что делает |
|---|---|
| `/market` | открыть окно рынка |
| `/market help` | список команд текстом |
| `/market browse [страница]` | что сейчас на рынке |
| `/market create giveaway` | черновик раздачи |
| `/market create trade` | черновик обмена |
| `/market create wanted` | черновик заявки |
| `/market create gift <ник>` | черновик подарка |
| `/market add` | положить предмет из руки в черновик (предмет сразу уходит в эскроу) |
| `/market want` | записать, что вы хотите получить (предмет остаётся у вас) |
| `/market publish` | выложить черновик на рынок |
| `/market take <лот>` | забрать раздачу или подарок |
| `/market offer <лот>` | предложить предмет из руки в обмен |
| `/market accept <сделка>` / `/market decline <сделка>` | ответить на предложение |
| `/market confirm <сделка>` | подтвердить обмен (нужно от обеих сторон) |
| `/market cancel <лот>` | снять свой лот, предметы вернутся |
| `/market mine` / `/market trades` | свои лоты и сделки |
| `/market deliveries` | забрать то, что вас ждёт |
| `/market admin info <лот>` | посмотреть чужой лот |
| `/market admin cancel <лот>` | снять чужой лот, вещи уйдут владельцу |
| `/market admin inspect <ник>` | что у игрока на рынке |
| `/market admin reassign <старый ник> <новый ник>` | передать лоты, эскроу и посылки после смены ника |

Черновик не хранится в памяти: это обычный лот в состоянии «черновик», поэтому выход из игры или перезапуск сервера
посреди его сборки ничего не ломает.

## Права

| Узел | По умолчанию | Для чего |
|---|---|---|
| `ourserver.market.use` | все | смотреть рынок |
| `ourserver.market.create` | все | выкладывать лоты |
| `ourserver.market.trade` | все | забирать и предлагать обмен |
| `ourserver.market.admin` | операторы | смотреть чужие лоты и снимать их |

Узлы обычные, LuckPerms работает с ними без каких-либо зависимостей от него в коде.

## Архитектура коротко

```
bukkit/   команды, слушатели, инвентарь игрока
   ↓
core/     правила и переходы состояний, без единого импорта Bukkit
   ↓
storage/  SQLite: миграции, запросы, журнал перемещений
   ↑
http/     локальный API v1
```

Подробнее — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Почему ядро не знает про Bukkit: так его можно проверить
тестами без запуска сервера, а это единственный способ честно проверить, что предметы не дублируются.

## База

`plugins/OurServerMarket/market.db`, SQLite в режиме WAL, `synchronous=FULL`. Схема и её версии —
[docs/DATABASE.md](docs/DATABASE.md). Миграции применяются сами при запуске.

Сердце схемы — таблица `item_movements`: журнал «откуда → куда», который нельзя изменить или удалить (триггеры
запрещают). Все остальные таблицы — это указатели на текущее положение вещей, а журнал позволяет проверить, что каждая
вещь в один момент времени лежит ровно в одном месте.

## API

`http://127.0.0.1:8788/api/v1/market/...`, заголовок `Authorization: Bearer <токен>`. Полное описание —
[docs/API.md](docs/API.md), инструкция для бэкенда сайта — [docs/WEBSITE-INTEGRATION.md](docs/WEBSITE-INTEGRATION.md).

Сайт не может передвинуть ни один предмет: он только просит плагин выполнить действие, а плагин сам проверяет права.

## Безопасность

[docs/SECURITY.md](docs/SECURITY.md) — список проверенных сценариев (дюп, повторные запросы, разрыв соединения,
перезапуск сервера, полный инвентарь) и то, как каждый закрыт.

## Резервные копии

SQLite нельзя копировать «на живую». Правильно:

```bash
sqlite3 /home/ubuntu/minecraft/plugins/OurServerMarket/market.db \
  ".backup '/home/ubuntu/backups/market-$(date +%F).db'"
```

Важное: базу и мир надо восстанавливать **вместе**. Откат только мира при свежей базе — это массовый дюп.

## Восстановление после сбоя

[docs/RECOVERY.md](docs/RECOVERY.md). Коротко: при старте плагин возвращает эскроу, зависший под завершёнными лотами, а
всё, что требует заглянуть в инвентарь игрока, разбирается при его входе — по отпечатку инвентаря, записанному до
операции.

## Обновление

1. Соберите новый jar.
2. Остановите сервер (`stop` в консоли `screen`), **дождитесь полной остановки**.
3. Замените jar, запустите сервер.
4. В логе должно быть `Database ready ... schema version N` и, если что-то восстанавливалось, строка `Recovery: ...`.

Откат: положить старый jar обратно. Схема базы вперёд совместима в пределах одной версии плагина; если новая версия
добавила шаг миграции, для отката понадобится резервная копия базы.

## Если что-то пошло не так

| Симптом | Причина |
|---|---|
| В логе `The marketplace database could not be opened` | нет прав на `plugins/OurServerMarket/` или диск заполнен |
| `The marketplace API needs a token` | не задан `OUR_SERVER_MARKET_TOKEN` или `api.token` короче 24 символов |
| Предметы не выдаются | инвентарь полон, игрок мёртв, или AuthMe ещё не пустил его в игру |
| `Recovery: N stack(s) returned` при старте | сервер падал; предметы вернулись владельцам, смотрите `/market deliveries` |
| В логе `handover(s) waiting for their player to log in` | сервер упал во время выдачи; решится, когда игрок зайдёт |

## Сборка

```bash
mvn -B verify
```
